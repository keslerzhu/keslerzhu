AI-Ready Location Intelligence — A Unified Lakehouse & Governance Architecture

Five layers from top to bottom: interactive, security, business logic, data lakehouse and data governance. The diagram draws only the fifteen connection rules supplied.

Interactive LAYER 1

WebBrowser, MapLibre, AI Agent, MCP Server, IoT, QGIS, ERP and CRM. People reach the map through the browser; the AI Agent reaches GIS, catalog and SQL tools through the MCP Server; QGIS works on the spatial database; IoT devices originate the live event stream.

Security LAYER 2

Keycloak and Apache Ranger. The rules specify no data flows for them, so they appear without arrows.

Business logic LAYER 3

Martin, Nominatim, Valhalla and GeoServer serve tiles, geocoding, routing and OGC services. Kafka, Flink and WebSocket carry live events to the map and to storage. Airflow brings ERP and CRM data into Spark.

Data lakehouse LAYER 4

Four columns: Analytical engine (Spark, Trino), Structured data (PostgreSQL/PostGIS, Iceberg), Extract & Transform (Computer Vision, OCR, Apache Tika, osm2pgsql) and Filesystem / Object storage (Images, Videos, Parquet, Microsoft Office, OpenStreetMap, PDF).

Data governance LAYER 5

OpenMetadata collects metadata from PostgreSQL/PostGIS, Trino and Kafka, and feeds MySQL and Elasticsearch. It also serves the MCP Server.
