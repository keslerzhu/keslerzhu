Reference Architecture: An Open Source GIS Platform with Data Lakehouse and Governance

Four layers from top to bottom: interactive, business logic, data lakehouse and data governance. The diagram draws only the thirteen connection rules supplied.

Interactive LAYER 1

WebBrowser, MapLibre, AI Agent, MCP Server, IoT and QGIS. People reach the map through the browser; the AI Agent reaches GIS tools through the MCP Server; QGIS works on the spatial database; IoT devices originate the live event stream.

Business logic LAYER 2

Martin, Nominatim, Valhalla and GeoServer serve tiles, geocoding, routing and OGC services. Kafka, the Message Processor and Web Socket carry live events to the map and to storage.

Data lakehouse LAYER 3

Three columns: the analytical engine (Spark/Sedona, Trino), structured data (PostgreSQL/PostGIS, Iceberg) and filesystem / object storage (Images, Videos, GeoParquet, Microsoft Office, OpenStreetMap, osm2pgsql).

Data governance LAYER 4

OpenMetadata collects metadata from PostgreSQL/PostGIS, Trino and Kafka, and feeds MySQL, Elasticsearch and Airflow. Trino reads Iceberg and passes its metadata on. Apache POI & Tika extract content from Microsoft Office documents. Apache Ranger sits in the layer.

Images, Videos and Apache Ranger appear in their layers without arrows because no connection was specified for them. PostgreSQL/PostGIS and GeoParquet are each a single component; every arrow to them is drawn to that one box. Where several sources feed several targets, the lines share a rail so the flow stays legible. A few line crossings remain where flows from different paths meet (the PostgreSQL/PostGIS to OpenMetadata line crosses the GeoParquet to Iceberg line).
