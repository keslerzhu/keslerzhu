Interactive LAYER 1

User, MapLibre, AI Agent, MCP Server and IoT. People reach the map through the browser; the AI Agent reaches GIS tools through the MCP Server; IoT devices originate the live event stream.

Business logic LAYER 2

Martin, Nominatim and Valhalla serve tiles, geocoding and routing. Kafka, the Message Processor and Web Socket carry live events to the map and to storage.

Data lakehouse LAYER 3

Four columns: OpenStreetMap with osm2pgsql; PostgreSQL/PostGIS; Spark/Sedona, Iceberg and GeoParquet; and Microsoft Office. The Spark/Sedona, Iceberg and GeoParquet column forms the lakehouse path.

Data governance LAYER 4

OpenMetadata collects metadata from PostgreSQL/PostGIS, Iceberg and Kafka. Apache POI & Tika extract content from Microsoft Office documents and pass it to OpenMetadata.

The Browser in rule 3 is drawn as the User node. PostgreSQL/PostGIS and GeoParquet are each a single component; arrows to them from the Message Processor and from the other sources are drawn to that one box. Where several sources feed several targets, the lines share a rail so the flow stays legible.
